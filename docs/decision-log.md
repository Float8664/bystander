## Сессия 2026-06-20 — fix: поля «параметры дома» теперь допускают временно пустой ввод

**Баг:** при стирании значения в полях «Квартир на этаже / Этажей / Подъездов» поле немедленно залипало на «1» и не давало ввести своё число. Причина: `onChange` немедленно коммитил `min` при `NaN`, React перерисовывал с `value={1}`.

**Решение:** `NumberField` теперь хранит локальный строковый стейт `localValue`. Пользователь видит то, что набирает (в том числе пустую строку). Валидация и вызов `onChange` происходят только в `onBlur` — когда поле теряет фокус. Если значение пустое или некорректное, подставляется `min`. Внешнее значение синхронизируется через `useEffect`, только пока поле не в фокусе.

## Сессия 2026-07-26 — UI: выравнивание «?», формулировки, «квартир» вместо «соседей», перенос блока N

Четыре правки интерфейса (математика модели не затронута):

1. **Выравнивание «?».** У `NumberField` и тумблера знакомства подпись — flex-контейнер, а у `RadioGroup` `<legend>` был обычным текстом, из-за чего иконка подсказки съезжала по вертикали. Добавлен `flex items-center` в `<legend>` — теперь все три контекста выравниваются одинаково. В `Hint` добавлен `shrink-0`, чтобы на узких экранах кружок не сплющивался в овал.

2. **Формулировки про знакомство соседей** — унифицированы на «знают друг друга» и лишены категоричности:
   - подпись тумблера и его `aria-label`: «Соседи знакомы между собой» → «Соседи знают друг друга»;
   - подсказка тумблера переписана («переложить ответственность на "кого-то другого"» — ближе к формулировке диффузии ответственности);
   - подсказка к типу дома: «Частный дом — соседи знают друг друга» → «...чаще знают друг друга»; там же «соседи почти незнакомы» → «чаще всего незнакомы», «высокая анонимность» → «выше анонимность». Причина — правило интеллектуальной честности: это тенденции, а не факты о конкретном доме.

3. **«Квартир» вместо «соседей» в блоке с числом N.** Модель считает квартиры, а не людей, — текст теперь это отражает: «В таком доме — примерно 20 квартир». `pluralNeighbors` заменён на `pluralApartments` (старая функция нигде больше не использовалась). Тексты ползунка-эксперимента и строка результата намеренно оставлены со словом «соседей» — по решению основателя.

4. **Блок с числом N перенесён вниз**, под секцию «Уточнить параметры дома», из которой это число и вычисляется. Подпись соответственно «настрой их ниже» → «настрой их выше».

**Проверка:** `npm run build` — чисто, `vitest` — 59/59. Визуально в браузере проверить не удалось: панель предпросмотра в этой среде не отображается, страница не выходит из состояния гидратации. Нужна ручная проверка на телефоне.

## Сессия 2026-06-06 — UI: калькулятор подключён к computeWitnessCount, вступление исправлено

**Что сделано:**

1. **Шаг 1 — слайдер N убран, число соседей вычисляется из формы дома.**
   Над калькулятором — строка «примерно N соседей-свидетелей». Ось X на графике
   динамическая (`niceAxisMax`), синяя точка «ваш дом» со значением.

2. **Шаг 2–3 — блок «Уточнить параметры дома» (раскрывающийся).**
   4 поля для многоквартирных домов (кв./этаж, этажей, подъездов, охват witnessScope)
   или 1 поле для частного дома («сколько соседних домов рядом»). Параметры дома синхронизированы
   в URL (`?apf=…&floors=…&entrances=…&scope=…`). При смене типа дома параметры
   сбрасываются к дефолтам. Старые URL `?neighbors=…` игнорируются без падения.

3. **Шаг 4 — ползунок-эксперимент (раскрывающийся, янтарный).**
   «А что если соседей было бы больше или меньше?» — amber точка на графике
   появляется только после первого касания слайдера и только если N эксперимента
   ≠ N дома. При изменении дома эксперимент сбрасывается.

4. **Вступление в `app/page.tsx` исправлено** — убрано жёсткое число «20 соседей»
   (которое после рефактора стало произвольным), заменено на «целый подъезд соседей».
   Провокация не спойлирует результат, остаётся приглашением прикинуть интуитивно.

5. **Текстовые подписи убраны с точек на графике** — «ваш дом — X%» и «эксперимент — X%»
   наезжали на кривую и друг на друга при близких N. Точки остались, подписи сняты:
   что есть что объясняет легенда над графиком, точные числа дублируются в блоке
   результата выше. Модель не менялась.

**Архитектурные решения:**
- `Calculator.tsx` — `"use client"`, вся логика состояния. `houseN = computeWitnessCount(shape, position)`.
  `modelInput.neighbors = houseN`. Формул в компоненте нет.
- `BystanderChart.tsx` принимает `houseN` и `experimentN: number | null`.
- URL-синхронизация защищена от Suspense-loop: `router.replace` вызывается только
  если `qs !== window.location.search` (diff-check).
- `parseShape` — мягкий парсинг URL-параметров с fallback на дефолты.

**Тесты:** 59/59, сборка чистая.

## Сессия 2026-06-06 — модель: N выводится из формы дома (computeWitnessCount)

**Что сделано:** добавлена чистая функция `computeWitnessCount(shape, position)` в
`probability.ts`. Число соседей-свидетелей N теперь ВЫВОДИТСЯ из параметров дома, а
не вводится вручную. Это первый шаг ступени «охвата» (см. `model-rationale.md`).

**Новые типы (`types.ts`):** `WitnessScope` (`whole_building` / `my_entrance` /
`my_floor_plus_adjacent`) и `BuildingShape` (`apartmentsPerFloor`, `floors`,
`entrances`, `witnessScope`, `neighboringHouses?`).

**Новые константы (`constants.ts`):**
- `BUILDING_DEFAULTS` — типовые параметры по типу дома (иллюстративные стартовые дефолты):
  хрущёвка (3×5, 4 подъезда, my_entrance) → N=14; панель (4×9, 6 подъездов, my_entrance) → N=35;
  элитный ЖК (6×16, 3 подъезда, my_floor_plus_adjacent) → N=17; частный (neighboringHouses=4) → N=4.
- `POSITION_REACH_FACTOR` (corner 0.85 / middle 1.0) — множитель ОХВАТА, сознательно
  отделён от `MODIFIER_POSITION` (тот же 0.85, но влияет на вероятность, а этот — на N).
- `ADJACENT_FLOORS_SPAN = 3` — этажей в охвате при my_floor_plus_adjacent.

**Архитектурное решение:** `neighbors` в `ScenarioInput` остался как финальное N.
`BuildingShape` — отдельный тип; UI передаёт N через `computeWitnessCount` (второй заход).
Ядро (pIndividual / pAtLeastOne / diffusion / acquaintance / addressed) не изменено.
Потолка на N нет — большой ЖК с whole_building честно даёт сотни свидетелей.

**Тесты:** +18 новых (`witness-count.test.ts`), итого 59/59 зелёных. Покрыты:
разумные N по типам дома, witnessScope (my_entrance < whole_building), угловая ≤ средняя,
частный дом = neighboringHouses, эффект свидетеля сохранён на вычисленных N, адресный
режим сохранён, инварианты [0,1] при N в сотнях.

**UI** не тронут — следующий заход.

## Сессия 2026-06-06 — фикс: тултипы «?» теперь открываются по тапу на мобильных

**Баг:** подсказки `?` (компонент `Hint.tsx`) не открывались на мобильных.
Причина: CSS-only `group-hover:opacity-100` — на тач-экранах события hover нет.

**Решение:** `Hint.tsx` переделан на `"use client"` с `useState(open)`:
- Тап/клик по `?` открывает тултип (и закрывает повторным тапом).
- Тап вне (`mousedown` + `touchstart` через `document`) — закрывает.
- `Escape` — закрывает.
- `useLayoutEffect` проверяет `getBoundingClientRect()` после открытия и сдвигает
  тултип горизонтально (`nudge` в px), если он вылезает за край экрана. Стрелочка
  сдвигается в обратную сторону, чтобы всегда указывала на `?`.
- `max-w-[calc(100vw-1rem)]` — тултип никогда не шире экрана.
- Проверено: мобильный вьюпорт 375px (preview) + живое устройство (Chrome/Telegram на телефоне) — тап открывает, тап вне закрывает.
- `aria-expanded`, `focus-visible` — доступность сохранена.

## Сессия 2026-06-06 — фикс: позиция квартиры просачивалась в адресный режим

**Баг (заметил тестер):** при `addressed=true` (обращаюсь к конкретному соседу)
переключение угловая/средняя квартира всё равно меняло итог. Но позиция — это
фактор ОХВАТА (слышимость через общие стены), а к адресату обращаются напрямую,
охват к нему не применяется.

**Причина:** в `pAtLeastOne` и `computeResult` шанс адресата считался через
`applyModifiers(input)`, куда входит `MODIFIER_POSITION` (corner=0.85).

**Фикс:** шанс адресата теперь считается с принудительной `position: 'middle'`
(нейтральный 1.0) — `applyModifiers({ ...input, position: 'middle' })`. Остальные
N−1 соседей остаются обычными (позиция к ним применяется), поэтому при N>1 позиция
влияет на итог слабо (вклад адресата доминирует), а при N=1 — не влияет вовсе.

**Сопутствующее:** в `whyText.ts` в адресном режиме убрана фраза про угловую
квартиру (вводила в заблуждение). Решение задокументировано в model-rationale.md.

**Тесты:** +3 новых (N=1 — позиция не влияет; N>1 — влияет слабо <0.05;
контроль: в неадресном режиме позиция влияет заметно). Всего 41 тест, все зелёные.

**Проверено на живом устройстве:** при `addressed=true` переключение угловая/средняя больше не меняет итог.

## Сессия 2026-05-31 — два новых параметра модели: acquaintance и addressed

**acquaintance (соседи знакомы между собой):**
- Добавлен булев параметр `acquaintance: boolean` в `ScenarioInput`.
- При `true` `pIndividual` умножается на `ACQUAINTANCE_FACTOR = 1.5` (иллюстративно).
- Эффект свидетеля сохранён: кривая `pAtLeastOne` по-прежнему убывает с ростом N.
- Тумблер в UI, тултип, строка «почему» реагирует.

**addressed (адресное обращение к конкретному соседу):**
- Добавлен булев параметр `addressed: boolean` в `ScenarioInput`.
- При `true` формула меняется: адресат не подвержен диффузии (`p_addr ≈ p_context`),
  остальные N−1 — по обычной формуле.
  `pAtLeastOne = 1 − (1 − p_addr) × (1 − p_regular)^(N−1)`
- Результат: кривая «на самом деле» становится высокой и почти ровной (слабо зависит от N).
- Неадресный режим (`addressed=false`) даёт ровно прежние результаты — проверено тестом.
- Коэффициент `ADDRESSED_DIFFUSION_REMOVAL = 1.0` — иллюстративный.
- Тумблер в UI с синим акцентом, тултип, строка «почему» реагирует.
- Источник механики: Darley & Latané (1968), вторая часть оригинального эксперимента.

**Тесты:** 38 тестов, все зелёные. 6 новых для addressed, 5 для acquaintance.

**Что в docs/VISION.md остаётся на будущее:**
- Соседи считаются из параметров дома (квартир на этаже, этажи, подъезды) — N выводится, а не вводится.
- Физика обнаружения: слышимость (звук/запах/двери/вентшахты) как отдельная ступень.
- Доля среагировавших из N как вторая метрика (другой угол на тот же эффект).
- Пресеты-контрасты сценариев («типичные» vs «критические» ситуации).

## Идея: вторая метрика и вопрос о пороге реакции (развилка, НЕ решено)

Возникло из вопроса: при большом числе свидетелей (например, 200 квартир видят
нарушение во дворе) — что происходит с реакцией?

ЧТО ВЕРНО И УКЛАДЫВАЕТСЯ В ТЕКУЩУЮ МОДЕЛЬ:
- Кривая выходит на асимптоту («полку»): после некоторого N разница между
  400 и 500 свидетелями почти исчезает, значение остаётся низким. Это уже видно
  на графике (правый хвост сплошной линии). Можно подчеркнуть это явно в UI/тексте.

ВОЗМОЖНАЯ НОВАЯ МЕТРИКА (пока нет в проекте):
- Не только P(хотя бы один среагирует), но и ДОЛЯ среагировавших из N свидетелей.
  По логике диффузии она тоже падает с ростом N. Это другой, наглядный угол на тот же эффект.
  Низкий риск: остаётся в рамках Darley & Latané. Кандидат на аккуратное добавление.

РАЗВИЛКА — ТРЕБУЕТ ОТДЕЛЬНОГО РЕШЕНИЯ (высокий риск для честности):
- «Пиковое/пороговое значение, при котором толпа НАЧИНАЕТ реагировать» — это НЕ
  эффект свидетеля. Это другая теория: социальные каскады / критическая масса
  (первый отреагировавший снимает блок с остальных). Явление реальное, но механизм
  почти противоположный, и в базовой модели Darley & Latané порога нет — там монотонное
  сползание без переломов.
- Подмешивать каскады в текущую модель = превратить честную модель одного
  подтверждённого эффекта в смешанную и эмпирически необоснованную. Это прямой
  риск «фальшивой научности», которого проект сознательно избегает.
- Если когда-то делать — то ЯВНО отдельным, помеченным блоком («а вот другая теория
  говорит обратное…»), как контраст, а не подмешивать в один расчёт.

## Правило: npm run build перед каждым git push

Перед каждым `git push` обязательно прогонять `npm run build` локально и убеждаться,
что сборка проходит без ошибок. Причина: продакшн-сборка (Vercel) строже dev-режима —
TypeScript-ошибки, которые не видны в превью, там падают и ломают деплой.

## Решения на момент старта

- Стек: Next.js (App Router) + TypeScript + Tailwind, графики Recharts, деплой Vercel.
  Причина: надёжность под вайб-кодинг, бесплатный деплой, SEO.
- Вся математика модели изолирована в src/lib/model — чистые функции, без React,
  покрыта тестами. В компонентах формул нет никогда.
- Коэффициенты модели — иллюстративные, легко заменяемые. Продукт
  образовательно-исследовательский, НЕ валидированный прогноз.
- Целевая структура модели — три ступени (обнаружение / охват / реакция-диффузия);
  подробности в model-rationale.md. Текущая модель плоская — осознанный первый шаг.
- Типы дома — это пресеты физических параметров, а не жёсткие категории.
- Порядок работы: одна фича за сессию, коммит после каждого рабочего шага.
